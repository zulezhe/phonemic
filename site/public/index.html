Why PhoneMic

Built for the moment your mic breaks — or the one you never had

Zero install on the phone

The phone side is a web page. Scan, allow, talk. Android and iOS both work.

Works on any network

Phone on cellular, PC on Wi-Fi? No problem. On the same network it silently switches to a ~6 ms direct link.

End-to-end encrypted

Keys are derived from your pairing code. The relay only ever sees ciphertext. No account, no telemetry.

Tiny & open source

A ~5 MB native app (Tauri + Rust). MIT licensed — you can even self-host the relay with one Docker command.

Privacy, in plain words

Your voice is the payload — so the design assumes zero trust in every server:

  • The pairing code on your screen is combined (HKDF-SHA256) with an ECDH handshake to derive the session key.
  • All audio is AES-256-GCM encrypted on your phone and decrypted on your computer. The relay forwards ciphertext it cannot read.
  • No account, no analytics, no third-party scripts on the connection page. The desktop app is fully open source.

FAQ

What's the latency?

About 6 ms round-trip on the same network (direct link), 30–120 ms via the cloud relay across networks. Tuned for voice input and calls.

Does it work when the phone screen locks?

The web page holds a wake lock while streaming, but iOS stops capture when you switch away. For long sessions keep the page in the foreground — it's designed for short bursts like dictation.

Do I need to install a driver?

Yes — apps need a virtual microphone device. The macOS app installs BlackHole (MIT) with one click. On Windows we guide you to VB-CABLE.

Can I run my own relay?

Yes. The relay is open source and ships as a Docker image: cd relay-server && docker compose up -d. Point the desktop app at it with one environment variable. See the self-hosting guide.

Windows version?

The core is cross-platform (Rust + Tauri). A Windows build with VB-CABLE support is on the roadmap.
